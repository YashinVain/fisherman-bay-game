# Ролики и скриншоты для каталога Яндекс Игр

Всё снимается из самой игры, без внешних программ: нужны только Node.js 22+ и Edge.
Перед работой запустить сервер: `node tools/serve.js`.

## Как это устроено

1. **Время идёт по кадрам** (`timemachine.js`). В странице подменены часы, таймеры,
   `requestAnimationFrame` и CSS-анимации: игра двигается ровно на 1/30 секунды за кадр,
   сколько бы ни снимался сам кадр. Случайность — с зерном, поэтому пересъёмка даёт тот же ролик.
   Замедление — просто меньший шаг времени, это настоящий слоумо без рывков.
2. **Исходники** — чистая игра без наложений (`films/src.js` → `src-h.js` ПК 2880×1620,
   `src-v.js` телефон 1620×2880). Играет «живой» игрок из `helpers.js` (`R.bot.human`):
   рука подъезжает к воде и замирает, подсечка через 0.2–0.4 с после поклёвки, палец в борьбе
   держат и отпускают не чаще чем раз в ~0.2 с, на свечке отпускают, рыбу из камыша ведут пальцем.
   Рядом записываются журнал звуков, положение пальца, положение рыбы и метки (заброс,
   поклёвка, подсечка, свечка, улов). Кадры лежат вне проекта: `tools/rec/paths.js`
   (`%TEMP%\fishing-tales-rec`), их можно смело удалять после сборки.
3. **Монтаж** (`edit.js` + `edit.html`, сценарии в `edits/`): клипы из исходников с камерой
   (зум, слежение за рыбой, тряска, пульс в такт), переходы (быстрый «смаз», наезд, вспышка,
   волна), стоп-кадры, графика поверх (`gfx.js`: огромные слова по буквам, логотип, плашка рыбы
   со счётчиком, рулетка, облачко, коллекция рыб, подсказки «Держи / Отпусти», кнопка
   «Играть бесплатно») и звук: музыка игры (`js/core/music.js`) + звуки игры по журналу + свои
   «вжухи» и удары. Склейки встают на доли музыки. Выход — MP4 (H.264 + AAC), упаковщик свой
   (`mp4.js`, на WebCodecs).
4. **Скриншоты** — `films/stills.js` (`shots-desktop.js`, `shots-phone.js`): настоящий кадр
   игры и яркая плашка-подпись.

## Команды

```
node tools/rec/rec.js tools/rec/films/src-h.js          # исходники для ПК (v — для телефона)
node tools/rec/edit.js tools/rec/edits/ad-baika.js h    # смонтировать ролик (h — ПК, v — телефон)
node tools/rec/edit.js tools/rec/edits/ad-baika.js h --publish   # …и положить в docs/promo/video
sh tools/rec/ads.sh                                     # всё подряд (в конце — и лёгкие копии)
sh tools/rec/ads.sh edit                                # только монтаж, исходники уже сняты
node tools/rec/light.js docs/promo/video/ad-baika-h.mp4 # лёгкая копия ad-baika-h-up.mp4 (до 4,9 МБ)
```

Ролики: `ad-baika` («Рыбацкая байка»), `ad-challenge` («Сможешь вытащить?»), `gameplay`
(видео геймплея, ≤ 28 с, настоящая игра почти всё время).

**Лёгкие копии** (`light.js` + `light.html`) нужны, когда файл в консоль приходится передавать через адресную
строку страницы, где за раз проходит около 1,5 МБ. Из готового MP4 они берут кадры, уменьшают их до 1280×720
(телефон — 720×1280), кодируют заново так, чтобы весь файл не превысил 4,9 МБ, а звук переносят как есть,
без пережатия. Рядом с большим роликом появляется `<имя>-up.mp4`; сами `-up` файлы скрипт пропускает, так что
ему можно отдать всю папку: `node tools/rec/light.js docs/promo/video/*.mp4`. Для заливки руками через
обычную форму консоли берите большие ролики.

## Проверка

```
node tools/rec/peek.js ad-baika-h [столбцов]            # контрольные кадры ролика одной картинкой
node tools/rec/see.js файл.mp4 "from=7&to=9&step=0.2"   # кадры из готового MP4 в нужные секунды
node tools/rec/verify.js docs/promo/video/*.mp4         # декодирует все кадры и звук, ищет замёрзшее видео и перегруз
```

`see.js` понимает ещё `w=1280` (кадры в натуральную величину) и `cx, cy, cw, ch` (вырезка в долях кадра),
например `"t=9.5&w=1080&cols=1&cy=0&ch=0.09"` — верхняя полоска кадра целиком.

Страницы-помощники: `gfxtest.html` (вся графика на фоне кадра), `crop.html` (вырезки кадров),
`sheet.html`, `gallery.html`, `frames.html`, `audiocheck.html`, `light.html`.
